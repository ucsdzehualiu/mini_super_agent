# 演示步骤

一次完整会话，六句话。输出取自同一次运行，任务 id 前后一致。

准备工作：终端拉到 150 列 × 45 行以上，否则右侧详情区会被挤掉。启动 `python main.py`，光标已经在输入框。
Windows 下双击 `start.bat` 也行，它会自动把窗口设成这个尺寸。喜欢浏览器的话用 `start_web.bat`。

界面左下角是**对话区**，你说的每句话和系统的回应都在这里，包括"这条按规则跳过了"这种。右下角是任务表和 Trace 树。

不想手动敲的话，启动时加 `--demo`（或 `start.bat --demo`），进去后按 **F3** 也可以，会按下面的顺序自动播一遍。

下文引用的输出省略了每行开头的时间戳，实际界面会显示。

---

## 1. 一句话拆成三件并行做

```
帮我查一下成都周边徒步路线，排个两天计划，再写一版介绍文案
```

左侧 EVENT STREAM 出现三行：

```
EV-001 帮我查一下成都周边徒步路线，
   过滤 程序层: PASS  WORTH
   [拆单] 拆出 3 个任务  ['02e421', 'b10b75', '7a007f']
```

`[拆单]` 表示这条走了 Router。右侧 TRACE 树在运行中的样子：

```
▼ ● EV-001
  ├ ▼ ✓ Router 判断 [router]  0.21s
  ├ ▼ ● researcher-02e421 [worker]  0.9s
  │ ├ ✓ web_search#1 [tool]  0.88s
  │ └ ▼ ● web_search#2 [tool]
  ├ ▼ ● planner-b10b75 [worker]  0.4s
  │ └ ✓ make_plan#1 [tool]  0.31s
  └ ▼ ● writer-7a007f [worker]  0.5s
    └ ✓ draft#1 [tool]  0.42s
```

三个 worker 各带一套工具，几乎同时开始。运行中图标是 `●`，耗时会自己跳；结束后变 `✓` 并定格。三个都结束后，根节点下面会再出现一个 `Router 合成`，负责把结果组织成一句话回给用户。

底部状态行：

```
在做 3 · 等结果 0 · 等你批 0 · 完成 0 · 失败 0 · 无进展 0 │ Router 判断 1 次，省下 0 次 │ 你出手 0 次
```

记下「Router 判断 1 次」，下一步对比。

任务表里能看到三条任务各自的订阅键：`路线查证`、`路线排期`、`路线成文`。下一步的直通就靠它。

## 2. 补一句，不重开一条

```
路线那条再补一句：避开收费景区
```

```
   过滤 程序层: PASS  WORTH
   [直通] 直通 02e421（追加到正在跑的 Worker）
```

状态行：

```
在做 0 · 等结果 0 · 等你批 0 · 完成 3 · 失败 0 · 无进展 0 │ Router 判断 1 次，省下 1 次 │ 你出手 1 次
```

Router 判断仍是 1，省下变成 1，你出手变成 1。这句话没经过 Router：程序层看出它在说「路线」，直接投递给正在管路线的那条任务，并记了一次人工介入。

任务表里 `researcher-02e421` 的「在等/次数」列显示「人出手1次」。

因为投递时 worker 还在跑，这句是追加进它的上下文，树里没有多出执行段。如果 worker 已经结束，会拉回来重跑一次，但仍然是同一条 task，不新建。

## 3. 等外部结果的任务不占执行位

```
另外帮我订一张下周三去成都的机票，先看看航班和价格
```

拆出两个任务：`researcher-42e062`（航班查证）和 `planner-3294b1`（航班排期）。

planner 先启动一个外部作业，然后挂起等结果。这一瞬间任务表里是：

```
task               状态      来源链        在等/次数     耗时
planner-3294b1     ◔ 等结果  3294b1        等:航班结果
```

状态行里「等结果 1」。这期间你可以继续输入下一句，它不占人。

作业完成后调度器自己把它拉回来（「系统自己救」+1），拿到结果再往下走。整个等待在 Demo 里约一秒。

挂起时该任务的 `ended_at` 会被写死，恢复时另起一段执行。时间轴里这段是蓝色 `░` 标「停住不动」，不计入执行时间，原因见 README 的算法说明。

## 4. 要花钱的动作，停下来等人

```
排期里那步订票，帮我直接订了吧
```

状态行：

```
在做 0 · 等结果 0 · 等你批 2 · 完成 4 · 失败 0 · 无进展 0 │ Router 判断 3 次，省下 1 次 │ 你出手 1 次，系统自己救 1 次
```

「等你批 2」：第 3 步那条 `planner-3294b1` 拿到航班结果后发现计划里有订票动作，也来请示了；加上这一句产生的 `planner-e73e89`，两个都在等你。

「系统自己救」可能是一次也可能是两次，取决于作业返回时刚好轮到哪一次巡检。其余几项是确定的。

两条的挂起原因相同：「计划里包含不可逆动作（订票/下单），确认执行？」。

**操作**：方向键把光标移到 WORKER SNAPSHOT 表的某一行，状态行显示当前选中的 task id，然后

- **A** 批准。任务带上「人工批准」重新跑一次，状态变 `✓ 完成`，「你出手」+1；
- **X** 驳回。状态变 `✗ 已取消`。

批准一条之后：

```
在做 0 · 等结果 0 · 等你批 1 · 完成 6 · 失败 0 · 无进展 0 │ Router 判断 4 次，省下 1 次 │ 你出手 2 次
```

「你出手」和「系统自己救」是两个独立计数。Watchdog 注入、作业完成后的自动恢复算后者。混在一个数里就没有意义了。

## 5. 刚才那个，接着改

```
刚才那个介绍文案改成更正式的腔调
```

```
   [召回] 召回 7a007f → 续做 0c9ba1
```

它找到了第 1 步写文案的 `writer-7a007f`，派生一条新任务挂在后面。任务表「来源链」列：

```
writer-0c9ba1    ✓ 完成    7a007f→0c9ba1
```

为了确认它不是随手挑了最近结束的那条，第 3 步特意也留下了已结束的任务（`researcher-42e062`）。召回仍然选中了文案那条。

## 6. 没有信息量的话不处理

```
忽略我
```

```
EV-006 忽略我
   过滤 程序层: REJECT deny_keyword(忽略我)
   [拦截] 程序层: REJECT deny_keyword(忽略我)
```

模型调用次数没变。

## 最后：F5 看另外两个视图

**第一次按 F5**，切到时间轴：

```
时间轴  跨度 54.3s   并发峰值 3   同时忙 4.23s   串行需 6.01s   → 并行省下 1.8s
（其中 3.64s 是在等人/等结果，不计入并行收益）
关键路径  planner-3294b1 (第3次) → make_plan#1
researcher-02e421      ██  1.43s
                        ·  web_search#1 0.96s
                        ·  web_search#2 0.70s
planner-3294b1         ░░  停住不动
                        ·  make_plan#1 0.45s
                         ·  start_job#2 0.01s
```

跨度是整场时长，取决于打字快慢。真正有意义的是「同时忙」对「串行需」：这些 worker 串起来要 6.01 秒，实际同时只占 4.23 秒。

**再按一次**，切到任务来龙去脉，每条任务一行：来源链、订阅键、人出手和系统自愈次数。

再按一次回到树。

## 附：打转检测

Watchdog 判「无进展」需要单独跑，因为默认阈值不会在几秒内触发。压低阈值启动：

```bash
python main.py --watchdog 1 --suspect 3
```

然后输入：

```
<<LOOP>> 帮我查一下竞品定价
```

worker 会反复调用同一个工具。几秒后告警区出现（下面两行是实际运行的原样输出）：

```
11:09:26  INFO  researcher-230cd1       注入提示（第 2 次连续调用）：你已经连续
11:09:26  WARN  researcher-230cd1        连续调用 2 次 → 无进展，已注入提示
```

任务状态变 `⚠ 无进展`。Watchdog 没有 cancel 它，只是往它的上下文里注入一条提示让它收尾。这条注入记在「系统自己救」上。
